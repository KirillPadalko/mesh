# Исправления проблем связи и аудио вызовов

## Выполненные исправления (2026-02-02)

### ✅ 1. Добавлены TURN серверы для WebRTC
**Файл**: `app/src/main/java/com/mesh/client/network/WebRtcManager.kt`

**Что сделано**:
- Добавлены бесплатные публичные TURN серверы (OpenRelay, Metered)
- Теперь WebRTC может работать через строгие NAT/firewall
- Используются как HTTP (порт 80), так и HTTPS (порт 443) endpoints

**Ожидаемый эффект**:
- Аудио вызовы должны работать в 90%+ случаев (вместо ~10% только на STUN)
- P2P соединения устанавливаются даже при симметричном NAT

---

### ✅ 2. Улучшена обработка входящего аудио
**Файл**: `app/src/main/java/com/mesh/client/network/WebRtcManager.kt`

**Что сделано**:
- Улучшен `onAddStream` с детальным логированием
- Добавлена правильная обработка `onAddTrack` для Unified Plan режима
- Аудио треки теперь корректно включаются на приеме

**Ожидаемый эффект**:
- Входящий звук в аудио вызовах должен быть слышен
- Логи покажут, добавляются ли аудио треки и в каком состоянии

---

### ✅ 3. Увеличен ACK таймаут
**Файл**: `app/src/main/java/com/mesh/client/transport/ChatTransport.kt`

**Что сделано**:
- Увеличен таймаут с 3 до 6 секунд
- Сообщения теперь дольше ждут ACK перед fallback на сервер

**Ожидаемый эффект**:
- Меньше ложных fallback на медленном соединении
- Сообщения реже дублируются через разные каналы

---

### ✅ 4. Улучшено переподключение WebSocket
**Файл**: `app/src/main/java/com/mesh/client/network/WebSocketService.kt`

**Что сделано**:
- Добавлено отслеживание времени последнего сообщения
- Переподключение пропускается, если соединение живое
- Добавлен CONNECTION_TIMEOUT (30 секунд) для определения мертвых соединений

**Ожидаемый эффект**:
- Меньше ненужных переподключений
- Батарея расходуется эффективнее
- Быстрее обнаруживаются реально мертвые соединения

---

### ✅ 5. Увеличен ICE candidate pool
**Файл**: `app/src/main/java/com/mesh/client/network/WebRtcManager.kt`

**Что сделано**:
- Увеличен с 5 до 8
- Улучшена connectivity в сложных сетевых топологиях

**Ожидаемый эффект**:
- Больше шансов найти рабочий путь для P2P
- Незначительное увеличение числа ICE кандидатов

## Как протестировать

### Тест 1: Аудио вызовы
1. Соберите и установите обновленное приложение
2. Попробуйте аудио вызов между двумя устройствами в разных сетях
3. Проверьте логи на наличие:
   - `Adding TURN server candidates`
   - `Audio track enabled for <peerId>`
   - `Audio track added via onAddTrack`

### Тест 2: Стабильность связи
1. Отправьте несколько сообщений
2. Переключитесь между WiFi и Mobile данными
3. Проверьте, что сообщения доходят без потерь

### Тест 3: Переподключение
1. Полностью отключите интернет на 10 секунд
2. Включите обратно
3. Проверьте в логах:
   - `Scheduling reconnect in Xms`
   - `Skipping reconnect - connection is alive` (не должно быть сразу после включения)
   - Успешное переподключение

## Что еще можно улучшить (в будущем)

1. **Собственный TURN сервер**: Развернуть coturn для полного контроля
2. **Адаптивный ACK таймаут**: Измерять RTT и подстраивать таймаут
3. **Метрики качества**: Отслеживать packet loss, jitter, RTT
4. **Улучшенный ICE restart**: Добавить debouncing и полярность
5. **Background restrictions**: Оптимизация для Android battery optimization
6. **Reconnection с экспоненциальным backoff до сетевого события**: Ждать Network Callback вместо таймеров

## Логи для отладки

При проблемах собирайте логи с тегами:
- `WebRtcManager` - WebRTC соединения и ICE
- `WebSocketService` - WebSocket подключение
- `ChatTransport` - Отправка/прием сообщений
- `NetworkService` - Сетевые события

Команда для фильтрации логов:
```bash
adb logcat | grep -E "WebRtcManager|WebSocketService|ChatTransport|NetworkService"
```
